<hr />

**ArchiveTune** は単なるYouTube Musicのラッパーアプリではありません。ゼロから構築された完全カスタムの音楽プレイヤーです。音楽はプライベートであるべき、美しくあるべき、そして思い通りに動くべきだと私たちは考えています。音質にこだわり、快適な操作体験を求めるなら、これが最適です。

---

> [!IMPORTANT]  
> **利用可能地域:** お住まいの地域でYouTube Musicがサポートされていない場合、初回データ取得のために対応地域のVPNまたはプロキシが必要です。

## 📥 ダウンロード

- [Stable リリース](https://github.com/NatuneGroup/ArchiveTune/releases/latest)：`main`。
- [Nightly プレリリース](https://github.com/NatuneGroup/ArchiveTune/releases)：`dev`、`N` タグ。

更新チャンネルは Stable と Nightly の2種類です。同じ署名鍵を使うため上書き更新できます。
旧 Canary の最終版 `C202610141722`（`a1a04ea02`）は公開済みで、`canary` ブランチは凍結されています。
保存済みの Canary 選択は Nightly に移行します。更新確認はまず `update-feed` リリースの
`stable.json` / `nightly.json` を認証キーなしで読み、取得できない場合に GitHub API を使用します。

### 開発中の変更（未リリース）

- どのビルドでも Stable / Nightly を明示的に選べます。ビルド種別は未設定時の既定値だけを決め、
  更新候補はチャンネルと既知の新しいバージョンコードで確認します。
- 表示中の長い設定説明は有限回だけ自動スクロールし、画面の状態とアニメーション無効設定を尊重します。
  再起動が必要な変更は保存後に共通の「今すぐ再起動 / 後で」ダイアログで通知し、「後で」では自動再起動しません。
- 開発者設定と共通のプレイヤー・曲メニューに音響ヒートグラフを追加しています。
  開くだけでは解析せず、実行・キャンセル・再試行で時間と量を制限した音声を解析します。
  シーク可能なローカル file/content、対応する暗号化されていない現在のストリーム、完全な同一ソースのキャッシュが対象です。
  DRM やアクセス不能な入力は利用不可になり得ます。結果は推測であり、原音のロスレス性や実際の DAC 出力を証明しません。
- 既存 DSP の Oboe は 1.11.0、Signalsmith Linear は 0.6.5、libusb は 1.0.30 に更新。
  Stretch は 1.4.0、soxr は 0.1.3 のままです。エンジンや既定の音声方針は変更しません。
  libusb/soxr はアプリの CMake/Gradle で再ビルドする Android 用部分ツリーです。
  使用中の USB 出力は維持し、到達不能な旧 USB モジュールだけを削除し MIT ライセンスを保存しています。
- 歌詞の意味を持つ Unicode を保持し、文字体系の保守的な除外判定とメタデータ・かなに基づく読みを統合しました。
  SimpMusic も共通の組み込み・プロバイダー・AI 方針を使い、原文の空白と文字の結合を保持します。
  読みと単語時刻が一致しない場合は行単位で表示し、正確な言語判定や全言語の発音は保証しません。
- AI 翻訳は完全で有効な結果だけを保存し、失敗時は再試行できます。キャッシュと結果は設定・対象歌詞に結び付けます。
  DeepL の翻訳先は明示的に対応付け、ローマ字変換には使いません。
  ダウンロード要求の一時領域を分離し、Listen Together の遅延再試行を接続・要求に結び付け、
  Spotify の更新・ログイン・ログアウトを直列化しました。
- 日本語辞書は端末の主システムロケールの地域 JP のみを使い、IP 位置情報は取得しません。
  フォアグラウンドでの検討は永続化された一度だけで、Wi-Fi / モバイル回線を利用できます。
  オフラインでも検討済みとなりますが、手動再試行は可能です。明示的な無効化・削除を尊重します。
  取得・検証・辞書初期化は起動や描画を待たせません。13,343,016 バイトの固定 IPADIC データは
  オフラインのローマ字歌詞用であり、UI 翻訳や全言語用エンジンではありません。

実装、別担当の限定的な最終整理、3 件の独立ソースレビューと確認済みの修正は完了しました。
2026-10-15 の CI 前チェックポイントでは、固定 IPADIC データと本番 tokenizer を使うものを含む
113 件の新しいテストメソッドを統合済みですが、まだ実行していません。実際の同一コミットのビルド・lint・
単体テスト結果は候補 PR と [GitHub Actions](https://github.com/NatuneGroup/ArchiveTune/actions) を参照してください。
ソースレビューは CI 合格を意味しません。新しい dev ドラフト PR は別々の並列ゲートが両方成功した後にのみ、
履歴を保持してマージし Nightly とマニフェストを確認します。実機・表示・USB・全言語の動作確認は行っていません。

### 🛠️ 開発 & エンジニアリング
プロジェクトのビルドや貢献に興味がありますか？ArchiveTuneは高性能なKotlinスタックで構築されています。  
<a href="CONTRIBUTING.md"><b>ビルドと貢献ガイドを見る →</b></a>

JDK 21、Android compile SDK 37、NDK `30.0.16248370`、同梱の Gradle 9.6.1
ラッパーと再帰的なサブモジュールを使用します。動作対象は Android 8.0/API 26 以降です。
ビルド・lint は `./gradlew assembleGmsMobileUniversalDebug lintGmsMobileUniversalDebug`、
テストは `./gradlew :app:testGmsMobileUniversalDebugUnitTest` です。
現在の制約付きミッションでは実行を最終リモート CI に延期していますが、通常の開発者のローカルビルドは禁止していません。
[リリース手順とゲート](docs/claude/RELEASES.md)も参照してください。
