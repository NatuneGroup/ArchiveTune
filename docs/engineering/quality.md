# Quality gates

## Lightweight checks

Python 3.11+ is sufficient; no dependencies, JVM, Android SDK or network are needed:

```sh
python3 scripts/check_repository.py --worktree
python3 -m unittest discover -s scripts -p 'test_*.py'
```

The checker validates maintained Markdown links, skill frontmatter, documented
Gradle tasks against their CI workflows, module import direction, source-selection
contract independence, cross-module dependency versions and copyright preservation.
It rejects new files over 1 MiB and new Kotlin files over 1,000 lines. Already-large
files may shrink, but may not grow past their existing budget. Move an appropriate
component/data asset instead of raising a threshold to silence a finding.

To install the repository's lightweight hook:

```sh
chmod +x .githooks/pre-commit
git config --local core.hooksPath .githooks
```

The hook reads index contents, so unstaged edits cannot conceal a broken staged
change. It never runs Gradle or rewrites source. Before replacing an existing
`core.hooksPath`, preserve/integrate the user's hooks rather than overwriting them.

CI checks committed changes with `--base <base-commit>`. Worktree mode includes
untracked, nonignored candidate files. Deleted files do not bypass reference checks.
Submodule source is checked only when it is initialized on the build host; a local
pass does not establish the missing submodules' dependency resolution.

The source-derived [toolchain/CI reference](toolchain.md) is generated by
`python3 scripts/update_toolchain_docs.py`. The same staged/worktree/CI checker
rejects stale generated content, so version and command changes need a matching update.
When changing issue classification, also run
`node --test .github/scripts/issue-labels.test.cjs`; this is not a hook prerequisite.

## Kotlin analysis on a build host

On a suitable JDK 21 host, or in the GitHub repository-quality workflow:

```sh
python3 scripts/check_code_quality.py --base <base-commit>
```

The isolated Gradle project in `quality/` needs no Android SDK or initialized
submodules. Spotless runs ktfmt's Kotlin style on changed production/test Kotlin
files, copied into an isolated temporary directory under `quality/build/`.
The formatter check never rewrites the checkout or analyzes a file through a symlink.
Detekt measures cyclomatic complexity, method length and nesting. PMD CPD detects
repeated blocks of at least 120 Kotlin tokens. Without a compiler classpath,
Detekt cannot run its semantic unused-private-code rules; the summary explicitly
reports `semanticAnalysis: false`.
Do not add suppressions or exclude changed production paths to obtain a pass.

Full Detekt/CPD reports and per-rule counts are retained under
`.factory/reports/code-quality/` and in the PR quality artifact. Existing findings
remain visible. The gate compares the base with the candidate using identical
rules; it rejects new findings, increased reported complexity and new duplication.
Source line movement and reductions of existing duplicated blocks do not create
new debt. Tool failures or missing/malformed reports fail the gate.

Formatting applies to whole changed files. Preview the report before applying a
formatter to a legacy large file, and do not mix unrelated mass formatting with
behavioral changes. No formatter runs from the pre-commit hook.

On a formatting failure, CI retains a proposed `formatter.patch` generated from
isolated copies. Review it before applying; the original checkout and failing
gate are unchanged. In constrained missions, keep full app compilation and tests
on GitHub-hosted runners.

For semantic unused-private-code checks and resolved dependency analysis, use a
complete SDK/submodule build checkout:

```sh
./gradlew --console=plain --stacktrace --profile \
  -I quality/dependency-analysis.init.gradle qualityInputs :app:projectHealth
python3 scripts/check_code_quality.py --base <base-commit> \
  --classpath-file quality/build/analysis-classpath.txt
```

The optional init script exports the actual variant compiler/Android boot
classpath, omitting entries absent on this host (they hold no classes; the count is
logged), adds dependency-analysis 3.19.2 to the root buildscript classpath only
for that invocation, and reports resolved external runtime artifact weights. Artifacts
over 20 MiB are flagged for review; project modules are not weighed. Weight alone is not
proof that a dependency is unnecessary. Review the generated dependency advice for
runtime/reflection use before removing anything.
Compiler-backed analysis is manual/weekly in `dependency_health.yml`, not added to
ordinary pushes or release packaging. Host-specific classpath manifests stay
under ignored `quality/build/` and are not uploaded.
Only the documented GMS/mobile/universal Debug app variant is enabled during this
optional analysis invocation; normal build and release variant matrices are unchanged.
The plugin is applied to subprojects, which inherit the root classloader scope that
also holds AGP; the root project's aggregate report is not part of this analysis.
In `dependency_health.yml`, manual and reusable runs compare with the `semantic_base`
input (default `origin/dev`, through its merge-base with HEAD). Scheduled runs compare
with the parent commit. A base equal to HEAD is rejected because it compares a tree
with itself.

## Development container and environment

`.devcontainer/` supplies a digest-pinned JDK 21 image and Android SDK bootstrap.
It targets an x86_64 Docker build host, not the constrained Termux device. Opening
the container downloads the SDK/NDK through `scripts/setup_android.sh`; it does not
initialize or move gitlinks. Initialize required submodules only on an authorized
build checkout. Container configuration is not evidence that it has built or run.

Debug setup requires no provider sign-in. `.env.example` lists optional build-time
overrides and how to export them; Gradle does not implicitly load dotenv files.
Keep real values in ignored local configuration or the existing CI Secrets.
BuildConfig values are extractable from APKs, not server-side secrets.

## Unit-test coverage, isolation and intermittent failures

The manual unit-test workflow uses the optional, built-in JaCoCo init script:

```sh
./gradlew --console=plain --stacktrace --profile \
  -I quality/unit-tests.init.gradle \
  :app:testGmsMobileUniversalDebugUnitTest :app:criticalPolicyCoverage
```

Workers restart between test classes, with at most two forks. This isolates static/
singleton state without changing production dispatchers or silently retrying tests.
The HTML/XML report includes all app bytecode. The enforced floor is 80% line and
70% branch coverage for the three source-selection contract files: matching and
direct-stream metadata, source order/overrides, fallback chains and cached-source
gating. This is a critical-policy threshold, not a claim of 80% whole-app coverage.
Missing policy bytecode or execution data fails the check.

For this constrained mission, full app compilation, lint, coverage and repeated/
semantic checks run on GitHub-hosted runners, not the smaller VPS. Open a
validation PR to `dev` for the build/lint gate, then dispatch `Unit tests` at the
same head. Its optional `extended_checks` input also calls the dependency,
security and stability workflows from that exact revision, without first merging
new workflow files into `main`. No release or branch-rule changes are needed.

For proactive instability detection on a build host:

```sh
python3 scripts/check_test_stability.py --repeat 3 --tests '*'
```

Use repeated `--tests <filter>` options for a smaller investigation. The
manual/weekly `test_stability.yml` job defaults to the full fork suite. Each
iteration forces the actual test task, retains its own JUnit XML/log and records
per-test timings. A failure remains a failure even if a later run passes.
Skipped/missing tests, changed test discovery and missing execution reports are
not reported as stable. Evidence stays in ignored `.factory/reports/test-stability/`.

## Naming and change discipline

- Kotlin/Java classes, objects, interfaces and type aliases use `PascalCase`.
- Functions and properties use `camelCase`; Compose UI functions use `PascalCase`.
- Constants use `UPPER_SNAKE_CASE`; package components use lowercase.
- Kotlin files normally match their primary type; test classes/files end in `Test`.
- Keep provider-required protocol names in serialized annotations, not renamed wire fields.
- Preserve legacy public/persisted names unless changing them is the task.
- Comments explain constraints or reasoning. Do not narrate obvious code.
- Add tests for behavior or an actual regression, not to pad a readiness score.
